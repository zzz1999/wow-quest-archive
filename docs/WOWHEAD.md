# Wowhead 缺失文字补充

Wowhead 作为额外网页参考。已有数据库文字、游戏变量、版本数值保持原样；缺失短对白、未完整解析的物品效果参与补充。网页显示实际语言、Wowhead 版本和采集日期，文本与证据随离线包保存，查看时不会连接第三方。

## 版本与范围

经典、巫妖、裂变、潘达利亚分别使用 `classic`、`wotlk`、`cata`、`mop-classic` 数据库；军团使用现行正式服。这是采集当时的网站版本，不是历史客户端 build 的证明。不同版本的数字 ID 不互相填补。

本轮检查有目标内容的缺失描述，以及有委托正文和交付关系的缺失完成对白；军团完成对白优先检查 ID 38600 及之后。测试、追踪、占位、自定义任务排除。部分即时交付和重复兑换任务本来就没有描述，空白不能直接认定为漏收录。

任务网页在本轮采集中返回 HTTP 403，因此停止该域后续请求，保留此前取得的结果。未取得的页面记录为 `no-page`，不表示 Wowhead 没有这条任务。公开物品提示接口单独采集；没有绕过挑战、改变身份或使用代理。

精确候选、实际请求、成功补充和跳过原因分别见 [来源清单](../sources/wowhead/manifest.json) 和 [检查报告](../reports/wowhead-audit.json)。不宣称已检查完全部任务，不把访问限制当作数据缺失证据。

## 接受规则

- 任务需要同版本 ID、相同语言标题和非空描述 / 目标上下文匹配。比对统一空白与 `$N` / `<name>` 等等价标记；保存原文不改写。仅提取主任务区域，排除评论、攻略和相关任务。
- 只补原数据库空字段，简中优先，其次繁中、英文。只收录完整短字段，每个版本任务合计至多 25 个分词；长段落跳过，不把截断片段当成完整对白。匹配用的长上下文只保存哈希，不发布整页；不补写剧情或自动翻译。
- 物品需要名称、品质、物品等级和效果法术匹配。本轮仅采纳不含数值调校的效果，例如传送和学习配方。恢复量、伤害、比例、持续时间或缩放继续依据原版本数据，不用正式服数值替代。
- 译名更改时可用同一物品的英文名核对身份，再选择其中文响应；所选响应必须具有相同品质、物品等级和法术引用。译文来源与用于核对的名称来源分别记录，避免仅因中文译名变化退回英文。
- 配方的通用学习法术 `483`，必须同时具有对应 `trigger=6` 学习目标，才能使用该物品页面的具体配方说明。页面附带的“制造出的物品”提示框不会混入配方效果。
- 已完整解析的效果不覆盖。属性、冷却、次数、售价、需求和奖励关系不变。“Wowhead 补充”是网页参考，不是历史客户端逐字复现的保证。

阅读器识别网页原文中的 `<name>`、`<class>`、`<race>`，按阅读设置显示玩家称呼标签；原文视角和导出保留这些标记。

## 文件与重建

`data/wowhead/<version>.json` 保存 `quests[id].fields[field]` 与 `items[id].effects[]`。每条包含原文、语言、URL、响应 SHA-256、采集时间和匹配依据。原任务 / 物品 JSONL 不变；构建时附上 `wowhead` 属性，因此网页 JSON / JSONL 导出包含补充与证据。直接读取原 JSONL 的研究程序须按版本与 ID 关联补充文件。

`sources/wowhead/manifest.json` 锁定原始请求及规范化文件哈希。完整网页只留在忽略的 `.cache/wowhead/captures/` 中，不发布。`reports/coverage.json`、原物品统计继续表示数据库本身覆盖量；增量看 `reports/wowhead-audit.json`。

日常 `npm run build`、`npm test`、`npm run validate` 使用已保存资料，不联网。显式采集、导入命令分别为 `node scripts/collect-wowhead.mjs`、`node scripts/import-wowhead.mjs`。采集支持 `--cached-only`（只整理已有响应）、`--items-only`（不请求任务网页）；遇到访问限制停止对应域。导入核对缓存与锁定哈希，普通网页构建不静默更新来源。

校验检查身份、上下文哈希、语言、空字段、法术引用和浏览器包一致性。测试覆盖文本提取、评论排除、配方嵌套提示、错误身份、数值变化、XSS 和变量保留。数据版权见 [数据声明](../DATA-LICENSE.md)。
